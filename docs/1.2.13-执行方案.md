# 1.2.13 执行方案

## 范围和执行方式

先完成本方案，再由 GPT-6.1 Sol、medium（中等推理）执行实现，主任务负责代码复核、测试和交付。

实际修改对象为 `flutter_app` 独立 Flutter 仓库，沿用现有 Controller / Repository / Domain / Widgets 分层，遵守根目录 AGENTS.md 的一致性与可复用原则；不修改父级 KMP 工程或用户未跟踪文件。

目标版本 `1.2.13+2033`。保持现有 OAuth、Android 签名、浏览器会话 User-Agent 和登录持久化行为，不重置凭据。发布前重新确认该版本未被占用。

## 1. 标签页部分为空，仅出现“在官网查看”

### 现状

- `TagPage` 已经有网格，但空列表没有明确空态，只剩常驻官网按钮。
- 当前 `RemoteBangumiRepository.tagPage` 请求 `p1/subjects`，按作品类型、标签、排序与页码筛选。
- 目前还不能确定所有失败标签的统一根因；必须区分请求参数/响应解析/分页错误、网络失败及服务端真实零结果，不把空数组一律视为故障。

### 修改

1. 使用中文标签、年份、空格、加号、斜线、日文等样本核对官方接口参数与真实响应结构，建立脱敏 fixture。
2. 修正标签 URL 编解码、类型、页码与 total 语义，禁止将分页总页数当总条目数。
3. 如果私有 API 对部分标签确有限制，提供经验证的只读数据回退；不能用普通关键词搜索假冒精确标签筛选，不能在鉴权/限流失败时盲目增加重试。
4. 明确显示加载、请求错误与可重试、真实零结果三种状态，官网按钮仅为补充入口。列表成功时必须显示条目卡，返回保留滚动位置。

### 验收

中文及特殊字符精确查询、首末页与重复页去重、零结果和失败不同、类型正确、点击结果进入作品详情。

## 2. 更新说明渲染 GitHub Markdown

### 现状

`UpdatePage` 使用 `SelectableText(result.notes)`，会原样显示 `##`、列表和链接语法。

### 修改

- 使用兼容当前 Flutter/Dart 的 Markdown 渲染组件，覆盖标题、列表、粗体、链接、行内代码、代码块和常见表格；主题跟随 MaterialTheme，窄屏表格允许横向滚动。
- 保留复制选择能力。按现有固定发布源获取说明，不把 Markdown 当可执行 HTML；链接只允许安全协议，远程图片不自动额外加载跟踪资源。
- 不改动下载摘要、安装身份/签名/版本核验流程。

### 验收

用真实发行说明和复杂 Markdown fixture 测试浅/深色、长链接、小屏幕、大字体及恶意协议；下载与安装按钮回归。

## 3. 图片向上拖动后松手闪动

### 现状与判断

`InteractiveViewer` 自身管理拖动和惯性，同时 `onInteractionEnd` 调用按实际图片尺寸计算的 `zoom.clampBounds()`；两套边界和松手阶段的矩阵更新有冲突风险。需要用纵向拖动、长图及横图复现后确认，不能只检查最终矩阵正确。

### 修改

- 统一手势期间、惯性期间与双击动画使用的位置边界，避免松手后突然切换坐标约束。
- 必要时调整惯性实现或采用单一受控变换；不能仅延时复位来掩盖闪动。
- 手势开始中止旧缩放动画；复位、切图、视口变化时停止旧动画，异步尺寸回调不得覆盖新图状态。
- 保持等比单路解码、原图保存、黑底、双指缩放、长按菜单和缩放后拖动；单指拖动不误判成切图。

### 验收

记录松手前后多个帧的变换，验证没有突跳/反复修正；包含适应视口、2.5 倍/8 倍、长图、横图、旋转窗口、双击动画中复位及连续切图。真实性能与 QQ 对比另列，不以组件测试冒充同机性能结论。

## 4. 主题取色调色盘，移除独立“外观”选项

### 修改

- 删除“我的/设置”中独立的 `appearance` 明暗切换项，避免与“主题颜色”重复；主题颜色页保留跟随系统/浅色/深色的统一控制，不删除图标、语言、减少动画等其他选项。
- 在现有莫奈/系统取色、图片取色、预设和 HEX 输入之外，新增色相与饱和度/明度可拖动的调色盘，并实时显示颜色和 Material 配色预览。
- 调色盘、HEX、预设和图片取色共用同一草稿状态。拖动不逐帧写磁盘，点击应用才持久化；取消不污染已保存主题。
- 为调色控件提供键盘操作、语义标签、数值输入备选与中/英/日文，系统动态色不可用时清晰回退。

### 验收

颜色转换、边界与无效 HEX、拖动同步、应用/重启持久化、未应用不保存，以及移除独立外观后旧偏好仍能正常读取。

## 5. 浏览器 Bangumi 链接唤起应用

### 现状和平台边界

Android 已声明 BROWSABLE HTTP/HTTPS Intent，但存在声明不等于浏览器必定自动交给第三方应用的问题。当前 Flutter 路由只覆盖作品、章节、人物、角色、用户和部分话题，缺少日志与标签等入口。

- Android 自动验证需要域名所有者在 `/.well-known/assetlinks.json` 中授权应用包名与签名；客户端不能代替 bgm.tv、bangumi.tv、chii.in 发布授权文件。
- Windows 目前是便携 ZIP；普通 HTTPS 的系统 App URI Handler 需要包身份和网站关联，不能承诺便携 EXE 能自动接管浏览器全部 bgm 链接，也不能注册成全局 HTTP/HTTPS 默认浏览器。

依据：[Android App Links 验证](https://developer.android.com/training/app-links/verify-applinks)、[Windows 网站应用关联](https://learn.microsoft.com/en-us/windows/apps/develop/launch/web-to-app-linking)。

### 修改

1. 扩充集中路由：日志、标签、作品话题、章节、用户等，统一三个受信域名和必要的结尾斜线/查询参数处理，拒绝伪造域名、危险 scheme、端口及异常编码。
2. 修复 Android 冷启动、后台唤起、已打开详情时的再次链接，避免启动和 Intent 双通道导致重复打开。避免不支持的路径被误送话题页。
3. 设置中加入 Android “允许打开支持的链接”引导入口，交给用户在系统界面确认；保留浏览器“分享至 Bangumi”和应用内粘贴链接。
4. Windows 保持命令行传入站内 URL 的跳转；如实现自定义协议，仅做明确可选的协议注册，不覆盖 HTTP/HTTPS。不能验证的自动唤起部分在说明中标明限制。
5. 对“在官网查看”避免发生浏览器再次唤起应用的循环：显式官网动作与应用内导航分开。

### 验收

解析与分发单测覆盖所有类型、无效链接、冷/热启动去重；原生入口编译验证。没有在线设备或网站授权时，明确标记浏览器到应用的实际验证未完成，不替用户修改系统默认关联。

## 6. 动漫等作品的“话题/日志”可进入详情

### 现状

`_TopicSection` 的 ListTile 缺少 onTap；`_ReviewSection` 的日志卡片也没有详情点击。已有作品话题详情读取和回复能力，但没有从这两个列表接入；日志还缺少统一应用内详情路由。

### 修改

- 话题卡正文点击进入现有 `TopicDetailPage`，确保类型为 subject、传递真实话题 ID；头像仍独立进入作者主页。
- 新增日志详情的模型/Repository/Controller/页面，读取 `p1/blogs/{id}` 和必要的内容信息，正确显示标题、作者、正文、时间与关联作品。富文本使用项目现有安全渲染链，不用单纯外部浏览器替代应用内详情。
- 接入官方支持的日志评论读取；可复用既有回复能力的部分沿用账号隔离、草稿和防重复提交机制。涉及写接口先核对参数与成功确认语义，不在真实账号自动发测试评论。
- 列表卡标题/摘要可点，作者头像独立可点，返回保持列表位置；新日志路由也服务通知和外部链接。
- 本轮以补齐现有列表的阅读与进入能力为主，不另行扩展长文日志发布器或新建话题编辑器。

### 验收

话题与日志 ID/类型正确、正文与头像点击目标不同、空正文/删除/权限失败可解释、返回状态保留、外部和通知日志链接进入同一详情；回复能力如接入须测试登录切换、失败保稿和不重复提交。

## 执行顺序、测试与发布

1. 先修图片拖动、标签数据与状态；再完成 Markdown 和主题；最后补齐日志/话题及外部路由，减少路由重复设计。
2. 按功能跑定向测试，日志保存在 build/verification，仅输出摘要和首个错误；公共层改动及发布执行完整回归。
3. 更新测试映射，新增用例不能仅以“源码包含某字符串”代替交互或协议验证。外网和真实账号写入不进入默认测试。
4. 主任务复核后提交、推送 GitHub；按现有 release.ps1 执行静态分析、完整 Flutter、Android 原生测试，构建 ARM64 APK 和 Windows 完整 ZIP。
5. 校验版本号递增、旧签名一致、原 OAuth 编译进入两端及 Windows 图标；Release 只写功能/修复，上传后比对摘要与来源提交。
6. 单独报告未验证项：实际浏览器关联、Android 真机手势/保存、QQ 同机性能。Windows 可做只读界面测试，不操作真实评论发布、已读清空、个人设置等生产写入。
