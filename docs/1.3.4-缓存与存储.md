# 缓存与存储管理

版本：1.3.4+2039。

## 页面与清理范围

入口为“我的 → 数据与网络 → 缓存与存储”。进入页面后按需扫描，不在个人首页初始化时遍历磁盘。展示可重建数据的磁盘占用、每类内容大小、文件数和保留数量，支持单项清理、全选/取消全选及批量清理。清理前展示所选分类，完成后重新扫描，并区分成功、使用中保留和失败可重试。

| 分类 | 内容 | 清理规则 |
|---|---|---|
| 图片磁盘缓存 | 封面、头像、评论图、新旧目录中的图片 | 同步更新缓存索引；有正在进行的图片读取或下载时保留 |
| 公开页面数据 | 日历快照及旧版快照 | 清除普通文件和旧缓存专用键，防止回退恢复旧内容 |
| 内存缓存 | 图片、页面响应、文本解析 | 清理可释放缓存，保留当前界面使用的对象 |
| 临时文件 | 图片传输、过期分片 | 只处理已知缓存目录内一天前的分片，近期文件保留 |
| 更新安装包 | 应用内下载的 APK、Windows ZIP、过期分片 | 只匹配本下载器命名的文件，下载期间禁止清理 |
| 诊断记录 | 本地图片诊断与上一会话记录 | 关闭写入窗口后清理；当前会话保留最小文件头 |

不会扫描和清除登录凭据、Cookie、主题语言等设置、远端收藏和用户导出的文件。这里的统计不是整个应用安装占用；图片索引继续交由原缓存库维护，避免升级后全部索引失效。

## 目录结构与迁移

普通可重建数据集中到平台提供的应用临时目录：

```text
bangumi-cache-v1/
  images/                     图片文件
  public/public-calendar-v1.json
  transfers/transfer-*/image.part
```

图片缓存保留原来的逻辑索引键。访问旧目录中的缓存命中项时，按文件复制到临时目标、校验长度、完成目标替换后再删除旧副本；不在启动时批量搬运缓存。迁移失败保留源文件，后续仍可通过原缓存失效流程重新获取。清理时暂停迁移，避免为了删除数据先复制数据；同时回收新旧图片目录中的遗留文件。

公开快照兼容原应用缓存目录的普通文件和旧加密缓存键。清理只删除该公开缓存键，不更改安全存储结构。写入代次和仓库读取代次隔离旧请求，清理前已开始的写入不会在清理后重新提交旧快照。

更新包继续使用原平台下载目录，避免改变 Android FileProvider 的安装授权路径。诊断记录继续放在应用支持目录的 diagnostics 下，保持与现有故障排查流程兼容。

## 并发与性能

- 图片缓存管理器不再提前创建随后被替换的默认实例。
- 磁盘扫描使用异步文件接口；目录提供器在一个管理会话内复用。
- 维护期间新的图片读取、下载和更新下载等待，已有任务运行时清理返回保留状态。
- 不递归删除缓存目录；逐个检查并删除所属文件，不跟随文件链接或受管根目录链接。
- 当前图片内存对象不强行释放；清理操作与应用关闭、页面返回之间不会重复提交。
- 清理图片缓存同时重置失败请求等待状态，允许立即重新尝试加载。
- 控制器与显示分离，状态和选择集合不可变，适配中文、英文、日文和窄屏大字体。
