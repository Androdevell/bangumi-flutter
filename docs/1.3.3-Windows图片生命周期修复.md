# Windows 图片生命周期调整与诊断

版本：1.3.3+2038。此轮按测试版验证，不将已有证据表述为所有闪退的根因。

## 调整依据

10 份原有转储中，7 份的指令窗口能匹配本地保留的两个 AOT 构建。配套内核生成符号并校验指令后，均指向 SafeImageFileService 的错误恢复与 ImageTransferFiles.release；其中部分在读取对象字段时已经发生访问违规。其余 3 份缺匹配构建，不套用符号。

已有转储不足以确认对象引用为何失效。仅修改 ImageDescriptor 或缓存容量没有消除已有样本中的异常。

## 本轮实现

- 每次下载持有独立 ImageTransferFile。写入、校验失败和内容流结束/取消共用一次释放 Future，不再在错误恢复时访问全局活动集合。
- 临时目录的旧分片扫描在创建首个新请求前完成，所有并发请求等待同一初始化。保留一天 TTL、所有权目录、链接检查和非递归删除规则。
- 流写入错误和关闭错误分别处理，关闭错误不覆盖先发生的断流错误。
- 确定无效、超限的图片等待 30 秒再自动请求，最多保留 128 个失败项；连接失败可以立即重试。手动重试会清除该 URL 的等待状态。
- 保留用户/DS 的纯 Dart 图片头解析方向，并修复长 JPEG 元数据绕过尺寸限制、PNG 签名不完整、BMP 负高度以及截断 JPEG 标记越界。无法确定尺寸时不直接放行。
- 保留 20 MiB 下载上限，当前工作区原有的 8 Mi 像素与 8192 单边限制。

## 本地诊断

显式以 `--dart-define=IMAGE_DIAGNOSTICS=true` 构建才启用。记录固定事件、递增请求编号与错误类别；不记录 URL、响应内容、路径、Cookie、Token 或账号。

内存事件与待写队列各限制 128 项，文件达到阈值后收缩为最近事件。Windows 主程序写入应用支持目录下的 `diagnostics/images.jsonl`，重启前的记录保留为 `images.jsonl.previous`。诊断文件不自动上传。写入失败不会阻断启动或图片读取。

测试版启用该编译开关；正式构建可不启用。OAuth 配置、浏览器 User-Agent 及 Android 签名沿用现有设置。

## 验证方式

新增 test/windows_image_lifecycle_test.dart，验证并发和重复释放、取消读取、原始断流错误、失败等待/手动重试、长 JPEG、PNG/BMP 校验、诊断容量与上一会话保留。

新增 tool/windows-navigation-stress.ps1 和 Dart 入口：运行实际 BangumiApp、日历和作品详情页面；匿名读取公开数据，使用独立测试缓存和内存偏好。每轮 300 次、间隔 650 ms，包含两天往返、七天循环、6 次详情进入滚动返回；额外放入曾触发超限的公开封面。三轮分别覆盖冷缓存、热缓存和 Liquid Glass。脚本检查进程退出码、完成标记，并保存 AOT 文件、请求/清理记录和结果。

修改前当天真实日历对照已完成 300 次且未崩溃；因此后续通过不能单独证明消除了全部触发条件。测试入口不恢复登录、不发送消息、不修改收藏。

完整应用需要继续在用户原操作和网络条件下验证。此轮不进行 SDK 整体升级，将 SDK 对照保留为仍可继续的调查方向。

## 本机已取得的结果

- 三轮各 300 次切换，退出码均为 0；合计 900 次切换、18 次详情滚动往返。每轮耗时分别为 217.0、215.2、212.3 秒。
- 冷缓存轮：117 次请求，84 次成功、33 次像素超限；117 次清理完成，564 次等待期内的重复请求被拦截。
- 热缓存轮和 Liquid Glass 轮：各 33 次超限失败、33 次清理完成；各 573 次等待期内的重复请求被拦截。正常封面使用已缓存文件。
- 完整 Flutter 回归：408 项可见测试成功、11 项环境相关测试跳过；静态分析无问题。Android 原生单元测试 14 项成功。
- 压力入口运行期间未新增 Bangumi 崩溃转储。隔离入口验证与最终主程序编译不同，仍需保留最终构建的符号依据并接受原操作验证。

发布采用 1.3.3 测试版，Windows 启用诊断。原始用户/DS issue 草稿及无关文件保留，未纳入提交。
