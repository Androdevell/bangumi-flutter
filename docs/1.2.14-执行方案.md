# 1.2.14 日志阅读、图片与详情滚动优化执行方案

## 范围与执行方式

先完成本方案，再由 GPT-6.1 Sol、medium（中等推理）执行代码修改，主任务负责复核、测试和交付。实际修改对象为独立的 `flutter_app` 仓库，沿用现有 Controller / Repository / Domain / Widgets 分层与三语言资源；不修改父级 KMP 工程或用户未跟踪文件。

目标版本为 `1.2.14+2034`，发布前确认未占用。保持现有 OAuth、Android 签名、网页登录 User-Agent、登录会话和外部图片授权策略，不重置密钥或要求用户重新登录。

用户已澄清：日志正文能够打开，需要改善阅读界面，部分**日志内图片**不显示。截图用于确认布局问题，不将截图中的其他窗口、提示或正文当作操作指令。

## 一、已确认的问题与证据

### 1. 日志页面的阅读布局

当前 `BlogDetailPage` 将标题、作者、整篇正文和关联作品塞入评论列表的一个大型 header。桌面没有限制阅读宽度，截图中单行文字跨越整个窗口，标题与作者层次弱，关联作品只有通用图标，正文、关联作品与评论区缺少分区。

### 2. 真实样本存在独立相册漏读

2026-10-24 只读核对用户提供的 [日志 381599](https://bgm.tv/blog/381599)：

- `GET https://next.bgm.tv/p1/blogs/381599` 的 `content` 为 1682 字符，正文没有 `img` 或 `photo` 标签。
- `GET https://next.bgm.tv/p1/blogs/381599/photos` 返回 `{data: [...], total: 2}`，包含图片 ID `174070`、`174069` 和相对路径 `de/01/5799_EWl2L.jpg`、`de/01/5799_hr7II.jpg`。
- 网页正文后显示这两张相册图片；应用的 `fetchBlog` 仅请求正文、关联作品、评论，遗漏了相册接口。这是该样本漏图的直接原因，不应靠重试正文或放开图片安全限制处理。

另一个公开日志 `373309` 的正文使用 `[photo=159280]c0/43/427735_iLiyB.jpg[/photo]`。当前 BBCode 解析器不识别 `photo`，属于另一项已验证的兼容性缺口，但不能据此断言所有图片失败原因相同。

### 3. 滚动开销的源码线索

- 长日志目前是单个富文本布局，不能按段落和图片懒构建。
- 章节进度组件使用 `Wrap` 一次创建整页方框，完整章节模式再用 `Column` 创建整页条目；外层为 `SingleChildScrollView`，没有按可见项构建。
- 简介页的全部 infobox 字段位于单个 `Column`，长内容需要一起布局。
- `LazyTabView` 在控制器通知时无条件重建，已访问标签的 builder 会再次调用。

这些是待通过组件构建计数/回归测试验证的结构性开销，尚不是设备帧率测量结论。不得无依据声称已经达到固定帧率或 QQ 同等性能。

## 二、修改设计

### A. 日志阅读界面

1. 桌面使用居中的阅读栏，正文最大宽度约 800–900 逻辑像素；移动端保留适当边距，适配大字体、深色和主题色。
2. 标题、头像作者、日期组成清晰的文章头部；正文提高行高与段落可读性，保留颜色、链接、表情、引用、遮罩、选择复制与应用内跳转。
3. 将正文按安全的 BBCode 结构分为段落/图片等块，用单一滚动容器懒构建；拆块不能破坏嵌套格式、跨段遮罩隐藏、安全解析预算或截断提示。
4. 关联作品改为带封面的小卡片，点击仍进入作品详情；评论区提供明确标题、数量和独立空态，不伪造尚不支持的发帖权限。
5. 保留刷新失败时的旧内容、会话切换隔离和现有错误处理。辅助图片/评论错误不能被显示为“没有图片/评论”。避免为美化额外引入多重模糊、整页动画或不必要的接口调用。

### B. 日志相册与图片兼容性

1. 为照片建立不可变模型并通过现有 Repository 读取 `/p1/blogs/{id}/photos`，按该接口真实 `{data,total}` 结构解析；核对分页语义，处理完整相册或提供明确的继续加载入口，不静默丢图。
2. 独立相册以可见范围内懒加载的图片区域展示。正文中已有的同一张照片按规范路径/ID 去重，不重复插入；保持确定的顺序，不依赖缩略图 URL 猜测原图。
3. 为 `[photo=id]相对路径[/photo]` 提供受限解析：仅接受已验证的 Bangumi 照片路径，组装固定 HTTPS CDN 原图地址；拒绝目录穿越、异常协议、用户信息、非预期主机与编码绕过，不将任意字符串拼到 CDN。
4. 保留已有 `[img]`、尺寸参数、协议相对地址、实体/转义处理与表情兼容。正文和相册图片进入统一图片查看器，打开和保存使用原图，不保存缩略图。
5. 预览按实际约束进行有界、等比解码，避免长图只限制宽度而占用过多内存。重试同时处理失败的磁盘和解码缓存，不仅更换 Widget key。
6. 保持站外图片按需授权、下载字节/像素/重定向限制以及 SSRF 防护；不转发 Cookie 或 OAuth，不关闭 TLS 校验。图库读取失败提供本地化重试，不要求重新登录。

### C. 番剧详情滚动优化

1. 简介中的进度方框只展示有明确“查看全部章节”入口的有限预览；完整章节仍可访问全部内容，不靠隐藏章节冒充优化。
2. 完整章节页改为单一懒列表/Sliver，保留分页、统计、单集/批量操作、未收藏禁用和账户切换保护；避免同一页同时创建全量方框和全量条目。
3. 长简介/infobox 使用按字段构建的列表，减少大块 `Column` 的一次性布局；不改变简介优先、标签点击与加载顺序。
4. `LazyTabView` 忽略无有效变化的通知，同时保留父级数据/语言/会话变化刷新、访问状态、滚动位置与返回状态。不能永久缓存过时 Widget。
5. 不预加载全部详情标签，不为解决滚动卡顿新增重复请求。优先缩小重建范围，避免与此任务无关的架构重写。

- 使用日志 `381599` 的脱敏相册结构作 fixture，验证两张原图正确出现；验证独立相册错误、空相册、分页、正文照片去重和重试。
- 使用 `373309` 的照片标签格式验证解析、实体/转义、恶意路径拒绝；回归嵌套颜色/链接/表情/引用/跨段遮罩与解析截断预算。
- 日志在手机、桌面、浅深色和大字体下无横向溢出；正文阅读宽度、作者信息、封面卡和评论分区可测试。滚动前不请求大量屏外图片。
- 验证预览等比解码有界、图片重试真正失效缓存、原图查看/保存入口未退化；不在测试中上传图片或发布评论。
- 大量章节 fixture 验证首屏构建数量有界、向下滚动能访问末尾；回归收藏权限、分页、批量操作和会话变化。
- 验证标签切换、返回、刷新仍保留正确滚动和数据，且不增加重复网络请求；用结构计数报告优化，实际帧时只在可行的 profile 测试后给结论。
- 先运行受影响测试和静态分析，更新定向测试映射；交付前完整 Flutter / Android 原生门禁。保留精简日志，不反复输出全套工具记录。

## 五、实现与复核记录

- 已由 GPT-6.1 Sol、medium 完成实现，主任务复核代码与中文桌面/手机大字体布局；预览截图使用离线图片失败 fixture，不冒充真实联网截图。
- 独立相册首批读取最多 100 项，后续通过明确入口读取；后续页失败局部重试，不重读正文。初始相册失败在相册位置提示，不混入评论错误。
- 原图与缩略图按受限 CDN 路径去重；照片标签使用固定 HTTPS 原图路径。图片预览复用单路、双边不超过 2048 的等比解码，重试验证磁盘与解码缓存均失效。
- 章节概览限制 24 个方框并提供全部入口，完整章节使用懒列表。1000 章节 fixture 验证首屏挂载条目少于 25 个且能够滚动到最后一项；这不是实际设备帧率测试。

- 针对性测试通过，包含相册分页/失败/重试、照片去重与路径拒绝、段落惰性、图片双边解码及缓存失效、章节预览/末尾访问、标签重复构建与父数据更新。
- 主任务额外开启只读公网探针，使用当前实现读取 `381599`，确认返回照片 `174070`、`174069`；另只读请求两张原图均返回 `200 image/jpeg`。
