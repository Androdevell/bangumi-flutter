# 1.3.0 执行方案

## 范围

修改 Flutter 独立仓库，不改父级 KMP 工程。版本 1.3.0+2035，沿用原 OAuth、签名及固定浏览器 UA；不清空缓存或会话来掩盖故障。

## Windows 启动异常

用户补充从 1.2.10 起异常。对比 1.2.9 与 1.2.10，该版本加入请求取消、流式限额和图片通道；本机事件日志存在 1.2.14 的 0xc0000005 原生访问异常，不能仅归因于 Dart 布局。当前 win_http 的取消清理会释放读取缓冲，和异步原生读取存在生命周期风险。移除业务对异步 WinHTTP 回调网络后端的依赖，改用 Dart IO 网络；系统代理保留显式代理、绕过和 PAC 解析（阻塞代理发现不得在 UI 线程执行），直连模式保留现有已验证 DNS/TLS 路径。保留 TLS 验证、请求预算、取消和图片安全限额。

真实窗口测试不发布评论或私信，不修改账号设置，不接触旧草稿；启动稳定性须单独验证，组件测试不能代替原生启动测试。

排查记录：替换 WinHTTP 异步后端后仍可复现，不能把后端调整描述成已修复启动崩溃。独立探针的会话恢复、日历读取和首张图片显示可持续运行；顺序检查封面时也会在部分图片触发访问异常，因此继续隔离图片检查与网络路径。临时将文件映射改为内存缓冲未改善，已撤回，保留原有字节与像素限制。

## 个人页面

- 去除时间胶囊 IntrinsicHeight 与富文本 LayoutBuilder 的冲突，改用普通流布局与独立时间轴装饰；大字体、长标题不重叠。
- 统计卡自适应列数和内容高度，数字与说明分层，保留点击筛选。
- 日志进入现有日志详情；目录新增只读详情、条目分页与站内导航，不把目录点击转到作者页。
- 作品标签的名称和计数使用不同字号、颜色和数字排版，保留完整语义与点击。

## 评论与章节详情

- 日志接入既有紧凑评论编辑器、草稿和会话保护。p1 写接口要求 Turnstile 且本应用 loopback 回调不在官方白名单，因此不伪造验证令牌；只读核对公开日志的已登录表单，确认 `ReplyForm → /blog/entry/{id}/new_reply` 传统路径仍存在。使用实际表单 CSRF 与已验证的传统 AJAX 路径，不自动重发未知结果。
- 章节评论入口改为章节详情：标题、原名、集数、播出日期、时长、类型与章节简介优先显示，然后评论；元数据失败明确提示，不将失败当空简介。
- 评论支持最早、最新、赞数排序，稳定排序并保留楼中楼归属；明确为当前已加载评论排序，不伪称服务端全量热榜。

## 私信

官方 p1 规范未提供私信接口，使用本站已存在网页登录通道与表单。增加收件箱/发件箱、分页、会话阅读和发送/回复入口；表单动作限本站已知私信路径，读取实际表单校验字段，不硬编码 CSRF。正文仅存内存，账号切换清理，禁止日志记录私信/Cookie；需要网页登录验证时明确引导。发送以明确响应确认，未知结果保留草稿且不重发。开发测试只用脱敏 fixture，不读取或发送真实私信。

## 验收与交付

新增 Windows 代理/取消回归、个人页窄屏大字体、目录与日志跳转、标签样式、章节元数据/排序、日志验证与会话隔离、私信表单安全与未知结果测试。先定向测试，再完整分析/Flutter/Android 门禁；Windows 实测启动、导航与滚动。发布 ARM64 APK 和完整 Windows x64 ZIP，校验升级构建号、原签名、编译内 OAuth、文件摘要，按功能/修复的统一格式推送 GitHub Release。未完成或未实测项必须在交付时说明。

用户要求先发布 Android：`1.3.0+2035` 仅发布 ARM64 APK 与对应校验清单；发布脚本通过 `-Platforms android` 保留全部测试、原签名和编译内 OAuth 检查，清单只记录实际构建平台。Windows 崩溃未解决，不生成或上传 Windows 包；后续修复按新的版本与提交重新验证。真实 Android 设备升级未实测。
