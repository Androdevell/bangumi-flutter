# Windows 图片加载崩溃排查与修复

## 已发布的 Android 版本

按要求先发布 `1.3.0+2035` ARM64 APK，保留原 OAuth 和签名。静态分析、423 项 Flutter 测试及 14 项 Android 原生测试通过；11 项依赖外部环境的测试跳过，真实 Android 设备升级未实测。源码提交 `c902b17503152edeb1325d247efb377f7266178e`，对应校验清单随 Release 发布。

## 稳定复现

Windows 事件日志中的正式版异常为 `0xc0000005`。排除基础启动、会话恢复和日历加载后，顺序读取日历封面也能复现，和必须同时显示多图无关。测试条目 `710874` 的原始大封面触发像素上限，而其 `/r/200/` 缩图正常。

独立程序直接调用原图片服务读取大封面，正式版在第一次请求即崩溃；同样的调试版正常抛出 `Image pixel limit exceeded`。为同一 AOT 内核生成符号并确认指令段一致后，原生回溯指向 `SafeImageFileService.get` 的异常分支及 `ImageTransferFiles.release`。从 1.2.10 开始，该校验的嵌套 `try/finally` 外新增了异步临时文件清理，与用户提供的首次故障版本吻合。

替换 WinHTTP 后端不能单独解决此问题；没有将其宣传成根因。普通临时文件创建/释放 1000 次、模拟图片成功/损坏及并发路径均不崩溃，不能用这些测试替代超限分支的 AOT 测试。

## 修改

将像素元数据检查抽到独立异步方法。先记录是否超限，释放描述符及缓冲后再抛出校验错误；外层仍负责临时文件清理。保留 20 MiB 下载上限、24 Mi 像素上限、HTTPS、地址检查和重定向限制；不关闭异常校验，不清空缓存或用户会话，不替换 OAuth。

实际大封面的独立正式版程序修改后连续 6 次正确返回超限错误并保持运行。加入 `tool/windows_image_smoke.dart`：本地模拟 3600 万像素 PNG 元数据、损坏数据与普通图片，交替执行 90 次；只检查元数据，不分配大图像素，不联网、不读取会话。

`tool/windows-image-smoke.ps1` 构建并运行 Windows 正式版入口，检查超时、进程退出码及完成标记；运行前要求没有 Bangumi 进程，防止单实例逻辑跳过测试造成假通过。正式发布门禁加入该项，随后明确使用 `lib/main.dart` 重建完整应用，避免把测试入口打包。
