# 评论、通知与图片查看器（1.2.12）

## 交互

- 评论阅读页底部使用输入框样式入口；编辑使用居中的窄底部面板，初始两行、最多五行。面板最高 480 逻辑像素且不超过键盘上方可用高度的 72%，不再切换全屏。
- 表情、插图、预览直接可用，完整格式工具可展开；长正文和大字体允许内部滚动。保留账号/回复目标隔离的内存草稿、关闭确认、发送去重和发布结果不确定时的核实流程。
- 首页与“我的”提供通知铃铛和未读角标。通知页支持最近消息、未读筛选、下拉刷新、点击跳转和将当前列表标为已读。
- 图片查看页、顶栏与系统栏统一黑底；长按或桌面右键打开保存菜单，也可点击顶栏下载。双击使用短缓动缩放，适应视口时快速横向轻扫切图；缩放后手势用于拖动图片。
- Android 原图保存至 Pictures/Bangumi，Windows 使用系统“另存为”对话框。保留 GIF/WebP 原始字节，不重新编码，不申请全盘存储权限。

## 通知边界与安全

接口依据 [Bangumi 官方私有 API 文档](https://bangumi.github.io/dev-docs/) 的 `GET /p1/notify` 与 `POST /p1/clear-notify`。

- 官方列表接口最大 40 条且未定义分页 offset，因此明确显示最近 40 条，不伪造无限分页。
- 仅应用在前台时每分钟检查未读，首轮延迟五秒以避免阻塞首页；切到后台取消定时器。不是应用被关闭后的系统推送，暂不申请通知权限或添加常驻服务。
- 加载列表不会自动清空通知。已读请求必须含明确且非空的当前列表 ID，绝不发送服务端代表“清空全部”的空请求体。
- 登录切换后清空旧数据；列表、未读刷新及写操作按会话校验。失败保留未读标记，过期请求不得覆盖新账号或新已读状态。
- 已支持的作品、章节、人物及话题优先应用内打开，其余受限于固定官网地址的浏览器回退，不执行正文中的任意地址。

## 图片资源和性能

- 沿用安全下载、重定向/地址校验、20 MiB 文件限额及像素限制；保存复用原图缓存，不另外携带登录 Cookie 请求图片。
- 预览解码边界由 4096×4096 收紧至 2048×2048，单个普通 RGBA 静态帧的理论最大像素缓冲由约 64 MiB 降为 16 MiB；这不是整页峰值内存实测，也不包含动图所有帧。
- 主图改为单一路径的 ResizeImagePolicy.fit 等比解码，不再同时构建缩放预览和未缩放原图，避免双重解码及双边指定尺寸导致的比例问题。
- 缩放变换复用图像，不随手势重新请求；移除重复渐入，图片单独绘制边界隔离；释放额外订阅拿到的 ImageInfo，避免动图帧句柄累积。
- 下载及文件选择结束再次检查展示权限。Android 保存只接受应用缓存下文件，通过 MediaStore pending 事务发布，失败清理半成品。
- 尚未做 QQ 同设备、同图集的帧时间/峰值内存对照，不宣称已经达到 QQ 性能。超长图的原尺寸分块渲染不在本次实现内。

## 验证

- 定向回归：紧凑编辑器尺寸、三语言大字体和键盘、草稿/发布失败、缩放边界、通知 ID 请求/筛选/未读数/账号切换/并发、保存原始字节与撤销权限。
- 正式发布执行静态分析、完整 Flutter 测试、Android 原生测试，以及 APK 版本/签名和 Windows 完整包校验。
- Android 相册实际写入、系统文件对话框、真实多指手势以及 QQ 对照仍需设备验证；自动化测试不能替代这些项目。
